# R09: Python and Python for data (research result, 26 October 2026)

Bottom line: Python 3.15 is the current feature release (3.15.0 on 2026-10-09, now 3.15.2 since 2026-10-25), five branches (3.11–3.15) are supported, 3.10 reached end of life on 2026-10-01,\[1\]\[2\] and the repository standard is out of date on three points: it omits 3.11/3.12 as still-supported, it implies 3.13 is still in full maintenance (it went security-only with 3.13.16 on 2026-09-30),\[3\] and its type-checker belief is wrong (Meta's Pyrefly has been stable 1.x since 2026-05-12; only Astral's ty is still pre-1.0).\[4\]\[5\]

Scope note: the research budget for this run covered the release status, tooling versions, packaging and data-library questions with primary sources. Several security, async, CLI and untrusted-input sub-questions could not be sourced in this run and are listed under section 9 rather than answered from memory, per Rule 3.

## 1. Summary

- **Current CPython (as of 2026-10-26):** 3.15.2, 3.14.10, 3.13.18, 3.12.16 and 3.11.18 are the latest patches of the five supported branches, all released 2026-10-25 as expedited security releases for the compromised eMudhra intermediate CA keys.\[6\]\[7\]
- **End of life:** 3.10 reached end of life on 2026-10-01 (final release 3.10.22); 3.9 on 2025-10-31. **3.11 reaches end of life in 2027-10 — within 12 months; flag it.**\[1\]\[8\]
- **3.13 is security-only:** 3.13.16 (2026-09-30) was its last full maintenance release; 3.13 now gets source-only security fixes until 2029-10 (3.13.17 was a special release with installers because of the CA incident).\[1\]\[3\]\[9\]
- **3.15 headline PEPs:** 810 (explicit lazy imports), 814 (`frozendict`), 661 (`sentinel`), 798 (unpacking in comprehensions), 686 (UTF-8 default encoding), 829 (package startup configuration files), 799 (`profiling` package and the Tachyon sampling profiler), 803/820/793 (stable ABI for free-threaded builds), plus typing PEPs 728, 747 and 800.\[10\]\[11\]\[12\]\[13\]
- **3.16:** alpha 1 shipped 2026-10-13; beta 1 (feature freeze) is 2027-05-04; final is planned for early October 2027 (PEP 826 says 2027-10-05, python.org and the devguide say 2027-10-06 — contested by one day).\[1\]\[14\]\[15\]
- **Action now:** upgrade pip, uv and certifi in every environment; python.org's own notice says "Upgrade certifi, pip, uv and sigstore now."\[2\]
- **Target for new projects:** run on 3.14 or 3.15; for libraries set `requires-python = ">=3.12"` and test 3.12–3.15 (plus `3.15t` if you ship compiled code), because NumPy 2.5 already dropped 3.11 and 3.11 ends in 2027-10.\[1\]\[16\]
- **uv** is at 0.13.5 (2026-10-21); 0.13.0 (2026-10-09) made 3.15 the default Python and changed tar handling; Astral announced on 2026-03-19 that it is being acquired by OpenAI.\[17\]\[18\]\[19\]
- **ruff** 0.16.0 (2026-07-23) raised the default rule set from 59 to 413 rules and formats Python code blocks in Markdown by default; 0.17.0 (2026-10-09) made the default target Python 3.11. Pin ruff — unpinned upgrades break CI.\[20\]\[21\]\[22\]
- **Type checkers:** mypy 2.4 (2026-10-01) supports 3.15 and parallel checking; Pyrefly is stable (1.4.0, 2026-10-14); ty is still 0.0.x (0.0.90, 2026-10-20) and in beta.\[4\]\[23\]\[24\]
- **pytest** current stable is 9.1.1 (2026-06-19); 9.2 is an unreleased draft.\[25\]\[26\]
- **pandas** 3.1.0 (2026-10-22) is current and requires NumPy ≥ 2.0.2; pandas 3.0 (2026-01-21) made Copy-on-Write the only mode and a dedicated `str` dtype the default.\[27\]\[28\]
- **NumPy** 2.5.x is current (2.5.4, 2026-10-10); 2.5 supports Python 3.12–3.14 and removed `numpy.distutils`.\[16\]\[29\]
- **Lock files:** PEP 751 `pylock.toml` is accepted; uv exports it (`uv export --format pylock.toml`) but keeps `uv.lock` as its source of truth; pip's `pip lock` and install-from-pylock are still experimental.\[13\]\[30\]\[31\]
- **Provenance is uneven:** on PyPI, pandas 3.1.0 shows "Full provenance" while ruff and mypy files show "No provenance", so PEP 740 attestation checks cannot yet be a universal gate.\[32\]\[33\]\[34\]

The devguide's table is the authority; dates in italics there "are scheduled and can be adjusted".\[1\] The 2026-10 patch wave was unusual: 3.14.8/3.13.16 (2026-09-30) and 3.10.22/3.11.17/3.12.15 (2026-10-01) were scheduled; 3.15.1/3.14.9/3.13.17 (2026-10-21) and 3.15.2/3.14.10/3.13.18/3.12.16/3.11.18 (2026-10-25) were expedited for the eMudhra/emSign CA compromise.\[3\]\[7\]\[9\]\[17\] PEP 790 had expected 3.15.1 on 2026-12-01,\[49\] so the published 3.15 bugfix calendar is now ahead of schedule; the next expected 3.15 date was not found.

**Small conflict to note:** python.org release pages date the latest patches 2026-10-25, while the Python Insider post announcing them is dated 2026-10-26.\[7\]\[50\] Use 2026-10-25 as the release date.

**3.15 headline features (PEP numbers confirmed against the 3.15.0 release page, the rc1 page and What's New):** PEP 810 explicit lazy imports (new `lazy` soft keyword); PEP 814 `frozendict` built-in; PEP 661 `sentinel` built-in; PEP 798 unpacking in comprehensions; PEP 686 UTF-8 default encoding; PEP 829 package startup configuration files; PEP 799 a dedicated `profiling` package and the Tachyon sampling profiler; PEP 831 frame pointers on by default (rc1 page); typing PEPs 728 (TypedDict extra items), 747 (`TypeForm`), 800 (disjoint bases); C API PEPs 803/820/793 (stable ABI for free-threaded builds, "abi3t"), 782 (`PyBytesWriter`) and 788. The JIT remains experimental.\[10\]\[11\]\[12\]\[13\] Notable 3.15 removals include `CGIHTTPRequestHandler` and `http.server --cgi`, the `sre_compile`/`sre_constants`/`sre_parse` modules, `pathlib.PurePath.is_reserved()`, `load_module()` on loaders, `codeobject.co_lnotab`, and `typing.no_type_check_decorator`.\[12\]

**3.16 schedule (PEP 826):** alpha 2 on 2026-11-10 and alpha 3 on 2026-12-15 fall within the next 6 months; beta 1 2027-05-04; rc1 2027-07-27; final 2027-10-05 per PEP 826, but 2027-10-06 per the devguide and python.org downloads page.\[1\]\[14\]\[15\] Treat the final date as "early October 2027".

**Recommendation — which versions to target and test:**
- Applications: deploy on 3.14 (mature ecosystem, bugfix releases until about 2027-10) or 3.15 once your dependencies publish 3.15 wheels; pandas 3.1.0 already ships `cp315` and `cp315t` wheels and mypy 2.4 runs on 3.15.\[24\]\[34\]
- Libraries: `requires-python = ">=3.12"`. Rationale: 3.11 ends 2027-10, NumPy 2.5 has already dropped 3.11,\[1\]\[16\] and supporting a branch through its final year costs more than it returns.
- CI matrix: 3.12, 3.13, 3.14, 3.15, plus 3.15t (free-threaded) for packages with C extensions; add 3.16 pre-releases as an allowed-failure job from alpha.
- Set ruff's `target-version` explicitly; ruff 0.17 silently defaults to 3.11 otherwise.\[20\]

### 4.2 Modern idioms, deprecations and removals (Priority 2)

Confirmed in this run (official docs):
- **3.14 features in "What we believe" are all correct:** deferred annotations (PEP 649/749, with the new `annotationlib` module), template strings (PEP 750, `string.templatelib`), officially supported free-threading (PEP 779), `concurrent.interpreters` (PEP 734), `compression.zstd` (PEP 784), and `tarfile` extraction defaulting to the `data` filter.\[36\]
- **`datetime.utcnow()` / `utcfromtimestamp()`:** deprecated, listed as pending removal "in the future" with no scheduled version. Replace with `datetime.now(tz=datetime.UTC)` and `datetime.fromtimestamp(ts, tz=datetime.UTC)`, as the 3.15 What's New directs.\[12\]
- **PEP 594:** the remaining 19 modules (aifc, audioop, cgi, cgitb, chunk, crypt, imghdr, mailcap, msilib, nis, nntplib, ossaudiodev, pipes, sndhdr, spwd, sunau, telnetlib, uu, xdrlib) were removed in 3.13.\[38\]
- **2to3/lib2to3:** removed in 3.13.\[38\]
- **3.15:** `profile` deprecated for removal in 3.17; `collections.abc.ByteString` and `typing.ByteString` removed from `__all__` ahead of removal in 3.17; the strptime `%d`-without-year form now raises `ValueError`.\[12\]
- **3.15 typing additions to adopt:** `TypeForm` (PEP 747), closed TypedDicts with `extra_items` (PEP 728), `sentinel` (PEP 661).\[12\] ruff 0.17 suggests `typing.TypeForm` on 3.15 (UP035).\[20\]

Not sourced in this run (listed in section 9): PEP 695 type-parameter syntax, `type` aliases, `Self`, `TypeIs`, `override`; dataclasses vs attrs vs Pydantic v2; `match`, exception groups, PEP 701 f-strings; `asyncio.TaskGroup`/`timeout`, `importlib.resources`, `zoneinfo`, `tomllib`. These are long-standing features of 3.11–3.13 that a supported-3.12+ codebase can use freely, but this run did not capture a quotable source for each, so the receiving session should source them from the relevant What's New pages before adding them to the facts files.

### 4.5 Security in Python (Priority 5)

Sourced in this run:
- **tarfile:** 3.14 made `filter='data'` the default.\[40\] Even so, CVE-2026-114583 (fixed 2026-10-25 in 3.15.2, 3.14.10, 3.13.18, 3.12.16, 3.11.18) showed `tar_filter` could be bypassed by "links replacing the destination".\[7\] Earlier patches (2026-10-01 batch) fixed "tarfile extraction-filter vulnerabilities allowing path escapes" and "a zipfile decompression bomb issue" (secondary summary).\[55\] Recommendation: on every supported branch, pass `filter="data"` explicitly (it documents intent and protects code that might run on older interpreters) and stay on the latest patch.\[56\]
- **TLS trust:** the eMudhra/emSign incident means environments must upgrade certifi (2026.10.19), pip (26.2.2) and uv (≥ 0.13.4); CPython's `ssl` module in the 2026-10-25 releases now distrusts the compromised intermediate keys "as a last resort".\[7\]\[9\]\[42\]
- **ruff S rules:** ruff includes bandit-derived `S` rules; whether they fully replace bandit was not sourced.

Not sourced in this run (section 9): `subprocess`/`shlex`, `pickle`/`marshal`, `yaml.safe_load`, `zipfile` extraction guidance, defusedxml status, `secrets` vs `random`, `hashlib`/`hmac`, SQL parameters, typosquatting/slopsquatting data.

### 4.6 Free-threaded Python (Standard 6)

3.14: "officially supported but still optional" (PEP 779 phase II), with a "roughly 5-10%" single-threaded penalty.\[36\] 3.15: still an optional build — no source says the GIL-free build became the default (phase III is "left for a future PEP"); the new abi3t stable ABI lets one extension build serve free-threaded interpreters, and the official macOS installers now install the free-threaded build by default (they do not disable the GIL in the default interpreter).\[12\]\[39\]\[57\] Ecosystem signal: pandas 3.1.0 publishes `cp314t` and `cp315t` wheels; NumPy 2.5 "improves free threading" and supports the free-threaded stable ABI; mypy 2.4's mypyc work targets free-threaded builds.\[16\]\[34\]\[58\]\[59\] When to use it: CPU-bound, thread-parallel workloads whose full dependency tree publishes `t` wheels; otherwise stay on the default build. A library-compatibility tracker URL was not sourced in this run.

### 4.7 Data (Standard 7)

- **pandas 3.x:** 3.0.0 (2026-01-21) made Copy-on-Write the only mode (chained assignment no longer modifies the parent, `SettingWithCopyWarning` gone), made a dedicated `str` dtype the default (PyArrow-backed if installed, otherwise NumPy object-backed), and, per the pandas 3.0.0 release notes, "pandas 3.0.0 supports Python 3.11 and higher" with a minimum NumPy version of 1.26.0. 3.1.0 (2026-10-22) speeds up `read_csv` ("typically two to three times faster than in 3.0") with parallel reads, adds `DataFrame.select`, and raises the floor to NumPy ≥ 2.0.2.\[28\] Migration actions: replace `select_dtypes(include="object")` string checks with `"str"`/`"string"`; delete defensive `.copy()` calls; install `pyarrow` explicitly.\[27\]\[60\] `read_excel` engines and `.xls` support were not sourced in this run.
- **NumPy 2.x:** 2.5.0 (2026-06-21) dropped Python 3.11, removed `numpy.distutils`, `numpy.row_stack` and others, deprecated setting `ndarray.shape` and in-place resize, and made `linalg.eig` always return complex arrays.\[16\]\[61\]\[62\]\[63\] 2.4.0 (2025-12-20) removed `numpy.in1d`, `numpy.trapz` and the `newshape` argument of `reshape`.\[16\]\[64\]\[65\]\[66\] Latest 2.5.4 (2026-10-10).\[29\]

## 7. Common mistakes (including AI-assistant failure modes)

These are failure modes that follow directly from facts sourced above; dedicated studies of AI-assistant Python errors were not found in this run.

1. **Stating 3.10 is supported, or that 3.13 still gets bugfix binaries.** Both are out of date (facts 12, 16). Assistants trained before October 2026 will repeat this.
2. **Describing Pyrefly as beta.** It has been stable since 2026-05-12 (fact 48).\[5\]
3. **Leaving ruff unpinned.** 0.16.0 changed the default rule set from 59 to 413 rules and broke CI for unpinned users (Simon Willison, secondary: "my various CI jobs all started failing thanks to new default Ruff checks and my unpinned \"ruff\" dev dependency").\[22\]
4. **Omitting `target-version`.** ruff now assumes 3.11,\[20\] which may miss or mis-fire `UP` rules for a 3.12+ project (fact 43).
5. **Using `datetime.utcnow()`.** Deprecated; use `datetime.now(tz=datetime.UTC)` (fact 31).\[12\] Conversely, claiming it is already removed is also wrong.
6. **Recommending `2to3` or `lib2to3`.** Removed in 3.13 (fact 33).\[38\]
7. **Importing PEP 594 modules (`cgi`, `telnetlib`, `crypt`, `imghdr`, …).** Removed in 3.13 (fact 32).\[38\]
8. **Assuming the default `tarfile` filter is enough.** CVE-2026-114583 bypassed `tar_filter` until 2026-10-25 patches (fact 6).\[7\]
9. **pandas 2-era code:** chained assignment (`df["a"][mask] = 1`), checking for `object` dtype to find strings, and relying on `SettingWithCopyWarning` (facts 57–58).\[60\]\[71\]
10. **Calling NumPy functions removed in 2.4/2.5:** `np.in1d`, `np.trapz`, `np.row_stack`, `numpy.distutils`.\[63\]\[65\]\[66\]
11. **Treating `pylock.toml` as uv's lock file.** uv's primary lock is `uv.lock`; pylock is an export (fact 64).\[31\]
12. **Assuming every PyPI package has PEP 740 provenance.** ruff and mypy currently publish none (facts 42, 67).\[32\]\[33\]
13. **Assuming Python 3.15 changes nothing for text I/O.** UTF-8 is now the default encoding regardless of locale (fact 24);\[12\] code that relied on a non-UTF-8 locale default will read and write differently.\[12\]
